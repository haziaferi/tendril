### Checked and clean, where the clean answer was not obvious

- **A Restore cannot misdirect a stale alarm.** `restoreFromBackup` calls `entryDao.deleteAll()`
  (`@Query("DELETE FROM entries")`) and re-inserts every entry with a *fresh* id — the snapshot
  mapper never carries `id`. Alarms armed before the restore are `PendingIntent`s keyed by the
  **old** ids, so if SQLite recycled ids, a stale alarm would fire against a different task and its
  Done/Skip action would resolve the wrong row. It does not: every id column is
  `INTEGER PRIMARY KEY AUTOINCREMENT` (checked in `25.json` for `entries`, `habits`, `reminders`,
  `blocks`) and a bare `DELETE FROM` leaves the `sqlite_sequence` row intact — run this session:
  three rows inserted (ids 1–3), `DELETE FROM t`, `sqlite_sequence` still `('t', 3)`, next insert
  id **4**. Both receivers also re-read the entry and return on missing or trashed. So 1.13's
  consequence is a *missed* notification, never a wrong one.
- **The merge does keep search in step.** The alarm seam is missed; the index seam is not —
  `PagesSyncEngine` calls `pageContentRepository.rebuildFtsForPage(pageId)` for every winning page
  in Pass 5 (`:669`), so a page that arrives from a peer is searchable immediately rather than at
  the next launch's `healIndex`. Worth stating because it is the same shape of seam as 1.3/1.13 and
  it is handled, which is what makes the alarm one an omission rather than a design.
- **The receivers' guards hold.** `OverdueAlarmReceiver` and `ReminderAlarmReceiver` both
  `getById(entryId) ?: return` and then `if (entry.deletedAt != null) return`, so an alarm
  outliving its entry costs a wakeup and nothing else.
- **The classic Kotlin shapes are absent.** Zero `GlobalScope`, zero empty `catch (e: X) {}`, zero
  `SimpleDateFormat` across `shared/src`, `Tendril android/app/src/main` and `Tendril windows/src`;
  four `runBlocking` sites, all at a start-up or window-open boundary, none on a hot path; the
  heaviest `!!` file has four. The `runCatching`-around-a-suspend-call hazard is reasoned about
  explicitly in `CalendarProviderSync.kt:175` and `SnapshotSyncOrchestrator.kt:1545`, and the
  remaining suspend-wrapping sites are all inside the sync pass, which runs `NonCancellable`.
- **The widget check-in goes through the shared use case**, not a reimplementation of the streak
  math, and refuses to write when App Lock is on. Only its re-arm is missing (1.12).

It was rebuilt the same session (commit below) to resolve each section to the **production
declarations** that cite it — the dense, deliberate side, 1,852 citations written directly above
what they describe — and report the ones no unit test names, with file and line. That is a
measurement rather than a pointer, and it is retroactively convincing: `§9.7`'s unnamed list has

session found by hand, and `HabitsWidget.onAction`, the Glance callback of row 1.12. Both blind

**The gap that remains is exact and worth stating.** Naming a symbol is not asserting on it: a
test that mentions `launchAndTouch` and checks nothing counts the same as one that pins it. Only
changing the code and watching a test go red settles that — which this repository does on every
fix and records in the commit message, where no command can re-check it later. So an *unnamed*
declaration is genuinely unexamined; a *named* one is only not-obviously-unexamined. Execution
coverage would not close it either, and is unavailable regardless: 0 of 231 cached Gradle groups
are jacoco or kover, so a coverage run is offline-blocked exactly as `connectedDebugAndroidTest`
is (2.5). What closes it, for any guard anyone asks about, is scoped mutation, and it is now
`tools/mutate.py`: patch out one single-line guard, run only the tests naming that symbol, expect
red, restore — inside a throwaway `git worktree` that carries your uncommitted work, so a crash
cannot leave the real tree mutated.

It discriminates, which is the only thing that makes a result mean anything. Two guards two lines
apart in the same file, same operator: `launchAndTouch`'s `if (locked()) return` came back
**KILLED** (`ViewOnlySurfacesGuardTest`), and `addEdge`'s `if (fromNodeId == toNodeId) return`
came back **SURVIVED** — row 2.6. Writing the missing test flipped it to KILLED, naming the test
that now catches it.

The costs are real and stated rather than discovered: one mutation is one Gradle run, about four
minutes for a guard in `shared/` and less elsewhere, so a whole section is an hour and `--list`
exists to choose. One operator only — delete a single-line guard — because that is the defect
shape this repository has (the alarm seam, the View-Only gates, the last-write-wins `continue`,
the self-connection refusal are each one line). An elvis `?: return` or a multi-line `if (…) {`
is reported as unsupported rather than skipped, so silence is never mistaken for a pass.
