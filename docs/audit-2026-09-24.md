# Audit — 2026-09-24 — fresh eyes: fallacies, inconsistencies, and the workflows that let them in

Everything in the repository that makes a claim: the process documents (`CLAUDE.md`, the
`tendril-audit` skill, the last audit, agent memory), the two specs against themselves and against
the code, the tools' claims about what they check, and the feature critiques' claims against the
tree. Audience `--personal`. The user asked for everything provable to be fixed, for no agent below
Sonnet, and for prompt variants to be scored by a sandboxed `claude -p`.

Every row is **executed** — a command, a test, a compiler or a read of the tool proved it here — or
a **hypothesis** with the step that would prove it; nothing in a hypothesis row was changed. Leads
came from three read-only explorers and five sweeps (all Opus); none was written down
before it was re-derived in-thread, and four did not survive that (listed at the end).

**The pattern behind most rows.** A number, a flag or a story is written into prose once; the tree
moves on; nothing re-reads it. `CLAUDE.md` said 598 LF files (616), five nested sessions (eighteen),
and that 1.8 was walk-pinned (it had a test); the skill named a `--unpinned` flag the tool never
had; the spec said four desktop destinations were stubs (none are). Re-counting fixes today's
numbers and rots again, so the structural fix is `tools/facts.py` (2.4): documents cite the command,
and a session that needs the number runs it. The second pattern is **a check that cannot go red**,
which this repository names and had several more of — in `audit.py` (2.1–2.3), in the prompt-eval
cases (2.5), and in the backlog workflow's test floor (2.7).
