# Code audit — 2026-09-04

A full read of all 139 Kotlin files (~17.4k lines), plus targeted review passes for
correctness, security, simplification, and a feature comparison against Notion and the
open-source apps in the same space.

**Correction — the build *can* be run here, and now has been.** This paragraph used to say it
could not: the network policy blocks `dl.google.com`, so Gradle cannot *download* AGP or any
androidx artifact. That was the wrong inference. Reachability only matters for a cold cache, and
`~/.gradle/caches/modules-2` already held every pinned version, with `gradle-9.7.1-bin` in
`wrapper/dists`. `./gradlew --offline :app:testDebugUnitTest` builds and passes.

The audit below was nonetheless produced by static analysis alone, and it cost something real: a
compile break (`viewModel.deleteForever(ids)` in a composable with no `viewModel` parameter)
shipped through this audit *and* a green CI run, because `androidx…compose.viewModel` is imported
and the name therefore resolves to something. Only a compiler distinguishes that from a real
property. CI now runs `:app:testDebugUnitTest` alongside the static checks for exactly that
reason. **Treat any finding below that has not been executed as a hypothesis.**

This file is the remainder: what was found and *not* changed, because it needs a product
decision, a larger change, or a device to verify against.

**Fixed since this was first written:** the missing add-dialog time pickers, which had left the
Merged tab permanently empty and stopped same-day tasks alarming; and "Delete forever" not
sticking, now handled by a `(kind, uid, purged_at)` tombstone that travels in the snapshot folder,
so a purge propagates to every device rather than only the one that made it — covering Entries as
well as Pages, since the same resurrection applied there across devices (spec §5.5.1.1). None of
it has been compiled or run — see above.

## 2. Sync and data-model gaps

**2.1 A page whose parent arrives later is orphaned permanently.** `mergePages` pass 2 resolves
`parentUid` only for records in `wonUids`. If the parent hasn't merged yet the child drops to
root — and on the next pass the child's `updatedAt` is no longer newer than local, so it is not
in `wonUids` and is never revisited. The class doc claims a "real two-pass fixup instead of
drop-and-heal", which holds only within one batch. Fix: re-resolve unresolved parents on every
pass, not just for winners.

> **Fixed**, as prescribed, with one distinction worth spelling out: Pass 2 now visits every
> record, but does two different things. A winner writes its tree position outright, as before; a
> non-winner may only *fill* a null parent or database that can now resolve, never overwrite one
> already set. Letting a loser overwrite would hand a stale record the power to move a page,
> which is exactly what losing on `updatedAt` denies it. Seven tests, three of them on that
> boundary rather than on the healing.

**2.2 A bound Recurrence column has two different string forms.**
`PageDatabaseViewModel.valueForCell` returns `period.toString()` (`"P7D"`) for the live proxy,
while `DatabaseSyncManager.crystallize` writes `formatIntervalValue` (`"1:WEEK"`). A view filter
comparing that column matches one form and not the other, and the displayed value changes on
unbind.

> **Fixed.** The underlying fault was duplication rather than formatting: the Period-to-interval
> conversion existed only inside `crystallize`, so the second call site reimplemented it as
> `Period.toString()` and drifted. It now lives in `Property.kt` beside the `formatIntervalValue`
> it produces, and both callers share it. Eight tests, including a round-trip through
> `parseIntervalValue` that ties the two ends of the column together.

**2.3 Notion import silently drops pages.** `NotionImporter` `continue`s on any `.md` whose
filename lacks a trailing 32-hex id, with no notice added — while §7.3.7 requires communicating
losses plainly, and `notices` exists for exactly this.

> **Fixed.** Skipping is still right — such a file genuinely is not a page from the export — but
> the skipped names are now collected and reported through `notices`, counted and listed (up to
> five, then "and N more"). Five tests.

## 3. Habits is half-wired

Three findings that are one story: the feature's data model is complete and its surface is not.

- ~~`NotificationChannels.HABITS` is created but **nothing ever posts to it**. There is no habit
  reminder scheduling anywhere in the app, so the channel shows up in Android's notification
  settings as a permanently silent entry.~~ *Fixed — `HabitReminderAlarmReceiver` posts to it,
  with the check-off action Loop's prior art is built around, routed through
  `CheckInHabitUseCase` like every other check-in path. Habits got a request-code region of
  their own: the two Entry schemes partition the low space by bit 0, so there was no free
  spelling a habit could adopt, and habit ids and entry ids are independent Room sequences that
  collide constantly.*
- ~~`Habit.time` is read but never written by any UI.~~ *Fixed — the add-dialog now offers one.*
- ~~`Habit.duration` has **no producer and no consumer** — it round-trips through the converter
  and the snapshot mappers and is otherwise unused.~~ *Fixed — the add dialog offers it beside
  the time (§3.3's "optional time + duration"), and the habits list renders it. Wired rather than
  removed because §3.3 specifies the field and §5.3 draws habits that have one.*
- ~~The Habits trash offers no "Delete forever" at all, so `HabitDao.deleteForever` has no caller
  and `PurgedKind` deliberately has no `HABIT` member yet. Adding the action means adding both.~~
  *Fixed — `PurgedKind.HABIT`, `PurgeRegistry.purgeHabit`, a `HabitTrashSheet`, and the habit
  merge honouring the tombstone. The trash affordance was reachable all along; it opened the
  Entry sheet on every tab, which is why the gap outlived the Entry fix.*

`CheckInHabitUseCase`'s own doc cites Loop/uhabits as the prior art. Loop's core interaction is
a per-habit reminder you can check off, dismiss or snooze from the notification. That is the gap.

## 4. Security residue

Three findings from the security pass were deliberately not fixed, because each needs a design
decision rather than a patch. The other four were fixed (see commit `dac9af4`).

**All three have since been fixed.** 4.1 and 4.2 had to be done together and in that order —
4.2 supplies the fact 4.1 asks for. The original text of each is kept below rather than
rewritten, since the reasoning is what made the dependency between them visible.

**4.1 A plaintext file is still trusted when a passphrase is set.** `decryptText` returns any
non-`TDRLENC1` file as trusted plaintext even when a key is configured, so AES-GCM's
authentication tag protects nothing at the system level: anyone who can write to the synced
folder injects records without knowing the passphrase. Not fixed here because "reject
unencrypted input" and "adopt a folder that was previously plaintext" are the same event, and
telling them apart needs 4.2.

> **Fixed.** `sync_meta.json` gives a folder an explicit "this is encrypted" marker, so a
> plaintext file inside one is an intruder rather than a folder mid-migration — the distinction
> that was missing. `decryptText` now refuses it, as "couldn't read this" rather than a delete,
> so the conflict sweep leaves it on disk to be inspected. An unencrypted folder is unaffected,
> encryption being off by default. Five tests, three of which fail if the refusal is removed.

**4.2 The PBKDF2 salt is a compile-time constant.** Documented as a deliberate trade (there is
no channel to exchange a random salt over, §9.4.2), and 210k iterations is a sound cost — but
the consequence is that one precomputed table works against every Tendril install, and equal
passphrases give equal keys. There *is* a channel: the folder itself. A small `meta.json`
holding a random salt, written beside the snapshots, removes the cross-user precomputation and
gives 4.1 the "this folder is encrypted" marker it needs. The bootstrap case (two devices
creating a salt before they have ever synced) is the part worth thinking through.

> **Fixed**, as `sync_meta.json`. Precedence is ordered so compatibility wins: the meta file if
> present; else, if the folder already holds ciphertext, it predates the file and stays on the
> compile-time salt (now `LEGACY_SALT`); else a fresh random salt, minted only on a write. A
> legacy folder also gains a meta file naming that same salt, which changes no key and supplies
> 4.1's marker. The bootstrap race is settled deterministically rather than left open — earliest
> `createdAt` wins across conflict siblings, ties broken on the salt bytes, so every device
> reaches the same answer with nothing to negotiate. The loser's own snapshots no longer open,
> and the write guard refuses rather than overwriting them. Eight tests.

**4.3 Checkbox-only mode exposes the whole shell over the keyguard.**
`setShowWhenLocked`/`setTurnScreenOn` are applied to the Activity while the composable shown is
the full `WorkbenchScaffold`, bottom nav bar included. Tapping a tab renders that destination
for a frame before the reverting `LaunchedEffect` runs — Settings among them. App Lock is never
consulted before enabling the bypass. The flags are now cleared on dispose (commit `dac9af4`),
which closes the leak past the lock screen, but the within-mode navigation is still open. Fix:
hide the bottom bar and back navigation while the mode is active, and refuse to enable it at
all when App Lock is on.

> **Fixed.** Both halves, as specified. `CheckboxOnlyState.activate` now takes an injected
> `appLockEnabled` predicate and returns false rather than activating — the two features
> contradict each other outright, so whichever was enabled second used to silently defeat the
> first. The refusal is explained in a dialog rather than being a button that appears to do
> nothing. `WorkbenchScaffold` hides the bottom bar whenever the keyguard-bypass flags are set,
> tied to the *same* flag that sets them so the control and the bypass cannot drift apart:
> removing the control removes the navigation path, instead of racing a `LaunchedEffect` that
> only fires after the offending frame is already drawn. Seven tests on the guard; the scaffold
> half is Compose and not unit-reachable.

## 5. Where Tendril sits against comparable apps

Comparison against [Notion](https://www.notionapps.com/blog/notion-database-properties-explained),
[AppFlowy and Anytype](https://affine.pro/blog/affine-vs-appflowy-vs-anytype),
[Obsidian and Logseq](https://itsfoss.com/comparison/obsidian-vs-logseq/), and
[Loop](https://github.com/iSoron/uhabits).

**Where it is already ahead of its open-source peers.** Local-first with no account, a real
Notion-shaped row-as-page database model, Canvas, backlinks, a graph view with focus depth, home
screen widgets, system Calendar Provider registration, and optional at-rest encryption — a
combination none of AppFlowy, Anytype, Logseq or Obsidian ships in one Android app. The
codebase's habit of recording *why* each decision was made is well above the norm for this
category.

**The gaps that matter most, in order:**

1. ~~**Nested blocks are stored but not rendered.** `Block.parentBlockId` exists, §3.1.1 specifies
   one level of nesting, `PageDetailScreen:250` renders only `parentBlockId == null`, and
   `NotionMarkdownParser` flattens on import *because* the renderer can't show them. This is the
   largest gap against every peer — indentation is table stakes in a block editor — and the data
   model is already there.~~ **Closed in `988f8c7` ("Render nested blocks, and let a block be
   indented"), with `4e63f08` ("Preserve one level of nesting on Notion import") closing the
   downstream half the same evening.** The fix was one filter and a new pure `outlineOf()` in
   `BlockOutline.kt` that emits each top-level block followed by its children — ordering logic,
   moved to where it can be tested, rather than drawn inside the composable. The second commit is
   part of the same closure and not a separate item: §7's flattening was never a format limitation,
   it was the importer refusing to write a `parentBlockId` the renderer would have made invisible,
   so removing the render filter removed the condition that decision rested on. This entry is
   marked here rather than deleted because it was ranked the **top** gap in this list, and a
   ranked list whose first item silently disappears reads as though the ranking changed.
2. **Whole-page last-write-wins loses concurrent edits.** §9.4 accepts this explicitly, and it is
   the right call for v1, but it is the one architectural decision that gets expensive to revisit.
   Every serious local-first peer has moved to CRDTs for text. The cheap intermediate step: keep
   LWW but stop *silently* discarding the loser — write the losing version beside the winner, the
   way Syncthing itself does with `.sync-conflict-` files.

   > **The intermediate step is done**; LWW itself is unchanged and still the v1 decision. A
   > losing page record is written as `<uid>.tendril-lost-<updatedAt>.json`, under a marker of our
   > own rather than Syncthing's, because this app's conflict sweep merges-then-deletes anything
   > carrying `.sync-conflict-` — the wrong fate for a copy being preserved. Two judgement calls
   > worth knowing: a record counts as lost only when it is strictly older *and* its content
   > differs from what replaced it (without vector clocks there is no way to tell a concurrent
   > edit from a stale copy, and identical copies would otherwise fill the folder); and nothing
   > expires these, matching how Syncthing's own conflict files behave. A purge clears a page's
   > preserved copies along with the page.
3. **Relation / rollup / formula properties.** Deferred in §7 and §10. Relations are what people
   actually reach for after basic tables; rollups and formulas can wait. Relation alone is close
   to the existing `PageRelation` shape.
4. ~~**Habit reminders** — see §3 above; the smallest of these to close and the most visible.~~
   *Done. Not the smallest on measurement — the scheduling decision is pure and testable, but the
   receiver, the notification and the AlarmManager wiring are none of the three, and only the
   first is covered by unit tests here.*
5. **Unlinked references.** Logseq's advantage over Obsidian's backlinks panel: show pages that
   mention this page's *title* without an explicit link. Tendril already has the FTS index and a
   backlinks panel, so this is a query, not a subsystem.
6. **Recurring tasks can't express "3 times a week".** `HabitFrequency(count, unit)` covers "every
   3 days" but not a weekly quota or specific weekdays; `Habit.kt`'s own doc records choosing
   this over a days-of-week model and notes the schema is not locked in.

**Not worth copying:** Notion's AI features, real-time collaboration, and its template gallery
all presuppose a server and an account, which §1 rules out. Anytype's IPFS/P2P layer solves a
problem an external Syncthing already solves here.

## 6. Repeatable checks

`tools/audit.py` now runs the mechanical half of this audit in seconds with no Gradle, SDK or
network. Eight checks, each encoding a defect this repo actually had, verified to go red when
its defect is reintroduced. `.github/workflows/audit.yml` runs it on every push.

It deliberately does not attempt what needs judgement — whether a comment is still *true*, or
whether a fix sits at the right altitude. Those still need a reader.
