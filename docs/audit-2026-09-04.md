## 1. Bugs left unfixed

Each was confirmed by reading the code, not inferred.

| # | Where | What |
|---|---|---|
| 1.1 | `ui/canvas/CanvasScreen.kt:243` | Edge tap-to-select is implemented inside `detectDragGestures`, whose callback only fires after touch slop — a tap never reaches it. Arrows cannot be selected, edited or deleted. It also consumes drags the outer `detectTransformGestures` needs for one-finger pan. |
| 1.2 | `ui/canvas/CanvasScreen.kt:189` | `EdgeEditor` mutates the captured `editingEdge` snapshot, so direction never cycles past one step, the label never updates, and typing a label reverts a just-made direction change. |
| 1.3 | `ui/pages/PageDatabaseScreen.kt:956`, `ui/pages/PageDetailScreen.kt:872` | `var text by remember(value) { mutableStateOf(value ?: "") }` on a field that writes on every keystroke: when the Room round-trip lands mid-typing, the `remember` key changes and the field resets to the older stored value, dropping characters. `BlockRow` in the same file already documents avoiding exactly this, with a `lastWrittenContent` guard — the cell fields don't use it. |

## 2. Sync and data-model gaps

**2.1 A page whose parent arrives later is orphaned permanently.** `mergePages` pass 2 resolves
`parentUid` only for records in `wonUids`. If the parent hasn't merged yet the child drops to
root — and on the next pass the child's `updatedAt` is no longer newer than local, so it is not
in `wonUids` and is never revisited. The class doc claims a "real two-pass fixup instead of
drop-and-heal", which holds only within one batch. Fix: re-resolve unresolved parents on every
pass, not just for winners.

**2.2 A bound Recurrence column has two different string forms.**
`PageDatabaseViewModel.valueForCell` returns `period.toString()` (`"P7D"`) for the live proxy,
while `DatabaseSyncManager.crystallize` writes `formatIntervalValue` (`"1:WEEK"`). A view filter
comparing that column matches one form and not the other, and the displayed value changes on
unbind.

**2.3 Notion import silently drops pages.** `NotionImporter` `continue`s on any `.md` whose
filename lacks a trailing 32-hex id, with no notice added — while §7.3.7 requires communicating
losses plainly, and `notices` exists for exactly this.

## 3. Habits is half-wired

Three findings that are one story: the feature's data model is complete and its surface is not.

- `NotificationChannels.HABITS` is created but **nothing ever posts to it**. There is no habit
  reminder scheduling anywhere in the app, so the channel shows up in Android's notification
  settings as a permanently silent entry.
- ~~`Habit.time` is read but never written by any UI.~~ *Fixed — the add-dialog now offers one.*
- `Habit.duration` has **no producer and no consumer** — it round-trips through the converter
  and the snapshot mappers and is otherwise unused.

`CheckInHabitUseCase`'s own doc cites Loop/uhabits as the prior art. Loop's core interaction is
a per-habit reminder you can check off, dismiss or snooze from the notification. That is the gap.

## 4. Security residue

Three findings from the security pass were deliberately not fixed, because each needs a design
decision rather than a patch. The other four were fixed (see commit `dac9af4`).

**4.1 A plaintext file is still trusted when a passphrase is set.** `decryptText` returns any
non-`TDRLENC1` file as trusted plaintext even when a key is configured, so AES-GCM's
authentication tag protects nothing at the system level: anyone who can write to the synced
folder injects records without knowing the passphrase. Not fixed here because "reject
unencrypted input" and "adopt a folder that was previously plaintext" are the same event, and
telling them apart needs 4.2.

**4.2 The PBKDF2 salt is a compile-time constant.** Documented as a deliberate trade (there is
no channel to exchange a random salt over, §9.4.2), and 210k iterations is a sound cost — but
the consequence is that one precomputed table works against every Tendril install, and equal
passphrases give equal keys. There *is* a channel: the folder itself. A small `meta.json`
holding a random salt, written beside the snapshots, removes the cross-user precomputation and
gives 4.1 the "this folder is encrypted" marker it needs. The bootstrap case (two devices
creating a salt before they have ever synced) is the part worth thinking through.

**4.3 Checkbox-only mode exposes the whole shell over the keyguard.**
`setShowWhenLocked`/`setTurnScreenOn` are applied to the Activity while the composable shown is
the full `WorkbenchScaffold`, bottom nav bar included. Tapping a tab renders that destination
for a frame before the reverting `LaunchedEffect` runs — Settings among them. App Lock is never
consulted before enabling the bypass. The flags are now cleared on dispose (commit `dac9af4`),
which closes the leak past the lock screen, but the within-mode navigation is still open. Fix:
hide the bottom bar and back navigation while the mode is active, and refuse to enable it at
all when App Lock is on.

## 5. Where Tendril sits against comparable apps

Comparison against [Notion](https://www.notionapps.com/blog/notion-database-properties-explained),
[AppFlowy and Anytype](https://affine.pro/blog/affine-vs-appflowy-vs-anytype),
[Obsidian and Logseq](https://itsfoss.com/comparison/obsidian-vs-logseq/), and
[Loop](https://github.com/iSoron/uhabits).

**Where it is already ahead of its open-source peers.** Local-first with no account, a real
Notion-shaped row-as-page database model, Canvas, backlinks, a graph view with focus depth, home
screen widgets, system Calendar Provider registration, and optional at-rest encryption — a
combination none of AppFlowy, Anytype, Logseq or Obsidian ships in one Android app. The
codebase's habit of recording *why* each decision was made is well above the norm for this
category.

**The gaps that matter most, in order:**

1. **Nested blocks are stored but not rendered.** `Block.parentBlockId` exists, §3.1.1 specifies
   one level of nesting, `PageDetailScreen:250` renders only `parentBlockId == null`, and
   `NotionMarkdownParser` flattens on import *because* the renderer can't show them. This is the
   largest gap against every peer — indentation is table stakes in a block editor — and the data
   model is already there.
2. **Whole-page last-write-wins loses concurrent edits.** §9.4 accepts this explicitly, and it is
   the right call for v1, but it is the one architectural decision that gets expensive to revisit.
   Every serious local-first peer has moved to CRDTs for text. The cheap intermediate step: keep
   LWW but stop *silently* discarding the loser — write the losing version beside the winner, the
   way Syncthing itself does with `.sync-conflict-` files.
3. **Relation / rollup / formula properties.** Deferred in §7 and §10. Relations are what people
   actually reach for after basic tables; rollups and formulas can wait. Relation alone is close
   to the existing `PageRelation` shape.
4. **Habit reminders** — see §3 above; the smallest of these to close and the most visible.
5. **Unlinked references.** Logseq's advantage over Obsidian's backlinks panel: show pages that
   mention this page's *title* without an explicit link. Tendril already has the FTS index and a
   backlinks panel, so this is a query, not a subsystem.
6. **Recurring tasks can't express "3 times a week".** `HabitFrequency(count, unit)` covers "every
   3 days" but not a weekly quota or specific weekdays; `Habit.kt`'s own doc records choosing
   this over a days-of-week model and notes the schema is not locked in.

**Not worth copying:** Notion's AI features, real-time collaboration, and its template gallery
all presuppose a server and an account, which §1 rules out. Anytype's IPFS/P2P layer solves a
problem an external Syncthing already solves here.
